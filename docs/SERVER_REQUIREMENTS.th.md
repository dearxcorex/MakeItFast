# ความต้องการเซิร์ฟเวอร์ — FM Station Tracker

**โครงการ:** FM Station Tracker (กสทช. ประเทศไทย)
**จัดทำเพื่อ:** ฝ่ายจัดซื้อ / ผู้บริหาร — คำขอจัดซื้อเซิร์ฟเวอร์
**วันที่:** 21 มิ.ย. 2569
**สถานะ:** ฉบับร่างเพื่อขออนุมัติ

---

## บทสรุปผู้บริหาร (หนึ่งหน้า)

**สิ่งที่ต้องการ:** เซิร์ฟเวอร์ Linux 1 เครื่อง เพื่อรันเว็บแอป FM Station Tracker
สำหรับทีมตรวจสอบของ กสทช. ระบบพัฒนาเสร็จและพร้อมใช้งานแล้ว ต้องการเพียงเซิร์ฟเวอร์
สำหรับใช้งานจริงเพื่อเปิดให้บริการ

**ข้อเสนอการจัดซื้อที่แนะนำ:**

| | |
|---|---|
| **เซิร์ฟเวอร์** | Linux VM 1 เครื่อง — **4 vCPU, RAM 8 GB, SSD 80 GB**, IP แบบ static, bandwidth 2 TB/เดือน |
| **ระบบปฏิบัติการ** | Ubuntu 24.04 LTS (หรือ 22.04 LTS) |
| **สิ่งที่รันบนเครื่อง** | แอป + ฐานข้อมูล PostgreSQL + Redis cache (อยู่บนเครื่องเดียว) |
| **สิ่งที่ต้องมีเพิ่ม** | ซับโดเมนภายใน (เช่น `fmtracker.nbtc.go.th`) + ใบรับรอง TLS (ฟรี) |

**ประมาณการค่าใช้จ่าย:**

| รายการ | ค่าใช้จ่าย | ประเภท |
|-------|-----------|--------|
| Cloud VPS (ระดับแนะนำ, สิงคโปร์) | **~$48/เดือน (~1,680 บาท/เดือน)** | ประจำ |
| — หรือ VM ภายในศูนย์ข้อมูล กสทช. | จัดสรรภายใน (ไม่มีบิลคลาวด์) | ครั้งเดียว/ภายใน |
| โดเมน + ใบรับรอง TLS | ฟรี (ใต้ `nbtc.go.th` + Let's Encrypt) | — |

**ทางเลือกการโฮสต์ 2 แนวทาง:**
1. **Cloud VPS** — เปิดใช้งานเร็วที่สุด ~$48/เดือน คาดเดาค่าใช้จ่ายได้ *แนะนำหากไม่มีพื้นที่ศูนย์ข้อมูล*
2. **VM ภายใน กสทช.** — ไม่มีบิลประมวลผลประจำ ข้อมูลอยู่ในองค์กร *แนะนำหากมีทรัพยากรเหลือ*

**สิ่งที่ต้องตัดสินใจ:** อนุมัติการโฮสต์แบบ Cloud VPS หรือ ภายในองค์กร

> *รายละเอียดสเปก, การจัดเก็บ, ความปลอดภัย และตารางค่าใช้จ่ายแยกตามผู้ให้บริการ อยู่ในหัวข้อถัดไป*

## 1. วัตถุประสงค์

เอกสารนี้ระบุทรัพยากรเซิร์ฟเวอร์ที่จำเป็นสำหรับการติดตั้งใช้งานระบบ **FM Station Tracker**
ซึ่งเป็นเว็บแอปพลิเคชันภายในที่ทีมตรวจสอบของ กสทช. ใช้ในการติดตามสถานีวิทยุ FM,
คำนวณค่าอินเตอร์มอดูเลชัน (intermodulation) และวิเคราะห์การรบกวนสัญญาณ
ปัจจุบันระบบอยู่ในขั้นพัฒนาและจำเป็นต้องมีเซิร์ฟเวอร์สำหรับใช้งานจริง (production)

ระบบนี้เป็น **เครื่องมือใช้งานภายใน** (สำหรับเจ้าหน้าที่ตรวจสอบ ไม่ใช่บุคคลทั่วไป)
การประมาณขนาดด้านล่างตั้งสมมติฐานว่ามีผู้ใช้งานพร้อมกันประมาณ **5–30 คน**
และฐานข้อมูลขนาดหลักหมื่นรายการ ทั้งนี้สเปกที่แนะนำเผื่อพื้นที่สำหรับการเติบโตไว้แล้ว

## 3. ซอฟต์แวร์ที่จำเป็น

เซิร์ฟเวอร์ต้องสามารถรันสิ่งต่อไปนี้ได้ ทั้งหมดเป็นซอฟต์แวร์ฟรี / โอเพนซอร์ส

- **ระบบปฏิบัติการ:** Linux — **แนะนำ Ubuntu 24.04 LTS** (22.04 LTS ก็ได้; Debian/RHEL ใช้ได้)
  ควรใช้รุ่น **LTS** เท่านั้น — รองรับถึง เม.ย. 2572 (24.04) / เม.ย. 2570 (22.04)
  หลีกเลี่ยงรุ่นชั่วคราว (24.10, 25.04) ที่รองรับเพียง 9 เดือน
- **Node.js:** เวอร์ชัน 20 LTS ขึ้นไป
- **PostgreSQL:** เวอร์ชัน 14 ขึ้นไป
- **Redis:** เวอร์ชัน 6 ขึ้นไป (หรือใช้บริการ Upstash Redis แบบ managed)
- **Reverse proxy:** Nginx หรือ Caddy (สำหรับ TLS + ให้บริการแอป)
- **ตัวจัดการโปรเซส:** systemd, PM2 หรือ Docker
- **ใบรับรอง TLS:** Let's Encrypt (ฟรี) หรือใบรับรองที่ กสทช. จัดหาให้

## 6. ความต้องการด้านเครือข่าย

- **ขาเข้า:** HTTPS (443) และ HTTP (80, redirect ไป HTTPS), SSH (22) จำกัดเฉพาะ IP ผู้ดูแล
- **ขาออก (ต้องไม่ถูกบล็อกโดย firewall):**
  - **แผนที่ (Map tiles)** — OpenStreetMap, CARTO, cartocdn (HTTPS) โหลดผ่านเบราว์เซอร์
    แต่ต้องเข้าถึงได้จากเครือข่ายผู้ใช้
  - **Let's Encrypt** — สำหรับต่ออายุใบรับรอง TLS อัตโนมัติ (หากใช้)
- แนะนำ **IP แบบ static** เพื่อให้ DNS และ allow-list ของ API คงที่
- **ชื่อโดเมน** — ซับโดเมนภายในของ กสทช. (เช่น `fmtracker.nbtc.go.th`)

## 7. ความต้องการด้านความปลอดภัยและการดำเนินงาน

- **บังคับใช้ TLS/HTTPS** — ระบบตั้งค่า cookie session และจัดการข้อมูลล็อกอิน
- **ความลับ (secrets)** ต้องจัดเตรียมและเก็บอย่างปลอดภัย (ไม่อยู่ในโค้ด):
  - `DATABASE_URL` — connection string ของ PostgreSQL
  - `SESSION_PASSWORD` — รหัสลับ 32 ตัวอักษรสำหรับเข้ารหัส session (`openssl rand -base64 32`)
  - `ADMIN_USERNAME` / `ADMIN_PASSWORD` — ผู้ดูแลเริ่มต้น (เปลี่ยนหลังล็อกอินครั้งแรก)
  - ข้อมูลรับรอง Redis/Upstash
- **สำรองข้อมูล:** สำรอง PostgreSQL อัตโนมัติทุกวัน (`pg_dump`), เก็บอย่างน้อย 7 วัน,
  เก็บไว้นอกเครื่อง (เช่น ที่จัดเก็บสำรองของ กสทช. หรือ object storage)
- **Firewall:** เปิดสาธารณะเฉพาะ 80/443, SSH จำกัดเฉพาะช่วง IP ผู้ดูแล
- **การเฝ้าระวัง (Monitoring):** แจ้งเตือน uptime + disk/CPU/RAM พื้นฐาน
- **อัปเดตระบบ:** เปิดการอัปเดตแพตช์ความปลอดภัยอัตโนมัติ

## 8. ตัวเลือกการโฮสต์ (สำหรับผู้จัดซื้อพิจารณา)

| ตัวเลือก | ข้อดี | ข้อเสีย | ค่าใช้จ่ายโดยประมาณ |
|---------|------|--------|---------------------|
| **A. Cloud VPS** (DigitalOcean, Linode, AWS Lightsail, Vultr) | ติดตั้งเร็ว ค่าใช้จ่ายคาดเดาได้ ปรับขนาดง่าย | จ่ายรายเดือน ข้อมูลอาจอยู่ต่างประเทศหากไม่เลือก region ไทย | ~$24–48 / เดือน สำหรับระดับแนะนำ |

> **คำแนะนำ:** ตัวเลือก **A** (Cloud VPS เครื่องเดียว 4 vCPU / 8 GB / 80 GB) หรือ
> ตัวเลือก **B** (VM ภายในองค์กรสเปกเทียบเท่า) ให้ความสมดุลที่ดีที่สุดระหว่างต้นทุน
> การควบคุม และความเรียบง่าย หากใช้คลาวด์ ควรเลือก **region สิงคโปร์/ไทย**
> เพื่อลด latency และเก็บข้อมูลใกล้ กสทช.

| VM บนฮาร์ดแวร์ กสทช. ที่มีอยู่ | จัดสรรภายใน (ไม่มีบิลคลาวด์) |
| ไฟ / ระบบทำความเย็น / rack | ภายใน |
| ฮาร์ดแวร์ครั้งเดียว (หากซื้อใหม่) | ~30,000–60,000 บาท สำหรับเซิร์ฟเวอร์ขนาดเล็กเทียบเท่า |
| ค่าใช้จ่ายต่อเนื่อง | เวลาดูแลของเจ้าหน้าที่ IT กสทช. |

> **ค่าใช้จ่ายประจำต่ำสุด** หาก กสทช. มีพื้นที่ศูนย์ข้อมูลอยู่แล้ว
> เหมาะที่สุดสำหรับการเก็บข้อมูลไว้ในองค์กรทั้งหมด

### A.4 ค่าใช้จ่ายประจำไม่ว่าจะโฮสต์แบบใด

| รายการ | ค่าใช้จ่าย | หมายเหตุ |
|-------|-----------|---------|
| โดเมน / ซับโดเมน | มักฟรีหากอยู่ใต้ `nbtc.go.th` | DNS ภายใน |
| ใบรับรอง TLS | ฟรี (Let's Encrypt) | หรือ กสทช. ออกให้ |
| แผนที่ (OSM/CARTO) | ฟรีที่ปริมาณการใช้ปัจจุบัน | หากใช้หนักอาจต้องซื้อแพ็กเกจ tile ภายหลัง |

### A.5 สรุป

- **คาดเดาได้และถูกสุด:** Cloud VPS เครื่องเดียว ≈ **$48/เดือน (~1,680 บาท)** รวมค่าประมวลผล
- **ถูกสุดโดยรวม:** VM ภายในองค์กร หาก กสทช. มีทรัพยากรเหลือ (ไม่มีบิลประมวลผลประจำ)
