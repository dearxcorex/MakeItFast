# Revoked-Station Alert (Off-Air Apply + UI Warning) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mark the 59 stations that appear in NBTC notice สทช2304/266/2569 (filtered to นครราชสีมา / ชัยภูมิ / บุรีรัมย์) as "revoked" in the DB, set `on_air = false` on the 22 that are still flagged on-air, and add a clear visual alert in the field-ops UI so an inspector immediately sees that broadcasting from a revoked station is illegal.

**Architecture:** Two cohesive layers built in order:

1. **Data layer** — add a persistent `revoked: Boolean` flag (plus a short `revoked_note` for traceability) to `fm_station`, extend `convertToFMStation` and the `FMStation` type, and update `scripts/audit-offair.ts` so `--apply` writes both fields atomically inside a single Prisma transaction.
2. **UI layer** — bubble `revoked` through the field-ops surface: a red REVOKED pill in the header, a banner explaining the legal context, an inspect-button color override (red instead of green), and a red-bordered map marker so the station stands out at any zoom.

**Supersedes:** Task 4 of `docs/superpowers/plans/2026-05-06-audit-offair-3-provinces.md` (which only flipped `on_air`). The audit script update in this plan does both writes; Task 4 of the older plan is no longer separately needed.

**Tech Stack:** Prisma 5 (`db push` style migrations against Neon Postgres), TypeScript, React 19, vitest, react-leaflet 5.

## Assumptions and out-of-scope

These are the calls I'm making — push back before execution if any are wrong:

- **The "revoked" flag is permanent until manually cleared.** Even if someone toggles `on_air` back to true, `revoked` stays true. The UI alert is the inspector's signal that the on-air state is illegal.
- **All 59 in-DB rows from the xlsx (STILL_ON_AIR + ALREADY_OFF_AIR) get `revoked = true`.** Only the 22 STILL_ON_AIR rows additionally get `on_air = false`.
- **`MISSING_IN_DB` rows (45) are NOT inserted.** They show up in the audit CSV but don't get rows created — that's a separate import problem.
- **`ON_AIR_UNKNOWN` rows (currently 0) are still NOT auto-flipped, even with this change.** They get `revoked = true` but `on_air` is left alone.
- **One revoked-source label per row** stored in `revoked_note` (e.g. `"NBTC สทช2304/266/2569"`) — enough to answer "why was this revoked?" in the UI tooltip.
- **No mobile-only re-design.** The same alert renders on desktop rail and mobile bottom sheet; both already share `FieldOpsCurrentFM`.
- **No interference-site equivalent.** Revoke notices apply to FM transmitters, not interference sources. INT panel is unchanged.

- [ ] **Step 3: Implement `chooseApplyTargets`**

Append to `src/utils/offairAudit.ts`:

```ts
export interface ApplyTargets {
  /** Every id_fm that should get revoked=true (every audited row that exists in DB). */
  revokeIds: number[];
  /** Subset of revokeIds that should also get on_air=false (only currently on_air=true rows). */
  offAirIds: number[];
}

/** Decide which DB rows the audit script should write. Pure — no I/O. */
export function chooseApplyTargets(records: AuditRecord[]): ApplyTargets {
  const revokeIds: number[] = [];
  const offAirIds: number[] = [];
  for (const r of records) {
    if (r.classification === 'MISSING_IN_DB') continue;
    revokeIds.push(r.idFm);
    if (r.classification === 'STILL_ON_AIR') offAirIds.push(r.idFm);
  }
  return { revokeIds, offAirIds };
}
```
